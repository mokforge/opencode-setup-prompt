# Python: Асинхронный код (asyncio)

## Когда async, а когда нет

- Async подходит для ввода-вывода с большим числом одновременных операций: HTTP, БД, очереди, сокеты.
- Не подходит для вычислений (нагрузка на процессор) и простого последовательного кода. Вычисления выноси в процессы (`ProcessPoolExecutor`) или потоки (`asyncio.to_thread`, если библиотека синхронная).
- Если проект синхронный, не переводи его на async ради моды. Один стиль на границе модуля: не смешивай синхронный и асинхронный интерфейс одной функции.
- Версию Python и принятые в проекте библиотеки (`aiohttp`, `httpx`, `anyio`, `trio`) определи по коду. Значения ниже написаны для стандартного `asyncio`; на Python до 3.11 нет `TaskGroup` и `asyncio.timeout`, используй `gather` и `wait_for`.

## Основные правила

- Корутина запускается через `await` или оборачивается в задачу. Вызов без `await` ничего не выполняет (частая ошибка).
- Точка входа одна: `asyncio.run(main())`. Внутри работающего цикла `asyncio.run` не вызывается.
- Блокирующие вызовы (`time.sleep`, `requests`, синхронные драйверы БД, тяжёлые файловые операции) внутри корутины запрещены: они замораживают весь цикл. Замена: `await asyncio.sleep`, асинхронный клиент или `await asyncio.to_thread(...)`.
- Ссылки на фоновые задачи храни (множество или `TaskGroup`): задача без ссылки может быть собрана сборщиком мусора до завершения.

## Параллельное выполнение

```python
import asyncio

async def fetch_all(urls: list[str]) -> list[str]:
    async with asyncio.TaskGroup() as tg:          # Python 3.11+
        tasks = [tg.create_task(fetch(u)) for u in urls]
    return [t.result() for t in tasks]
```

- `TaskGroup`: при ошибке отменяет остальные задачи и поднимает `ExceptionGroup`. Подходит, когда все задачи нужны для результата.
- `asyncio.gather(*coros, return_exceptions=True)`: собирает результаты и ошибки по отдельности; после вызова проверяй, что элемент не исключение. Без `return_exceptions` первая ошибка пробрасывается, остальные задачи продолжают работать.
- Ограничивай параллелизм: `asyncio.Semaphore(N)` или очередь с N обработчиками. Тысяча одновременных соединений убьёт сервис или лимит API.

## Таймауты и отмена

```python
async def with_timeout() -> str:
    try:
        async with asyncio.timeout(5):             # Python 3.11+, иначе asyncio.wait_for
            return await fetch(url)
    except TimeoutError:
        ...                                        # обработка и логирование
```

- `asyncio.CancelledError` не глуши. Если перехватил для очистки, выполни очистку и пробрось его дальше (`raise`). Не ловить `BaseException` целиком.
- Очистка при отмене: `try/finally` или асинхронный контекстный менеджер.
- Для `asyncio.shield` нужна причина: он защищает от отмены, но задача продолжит работу без владельца.

## Ресурсы и итераторы

- Соединения, сессии, клиенты: `async with` (общая сессия HTTP-клиента на приложение, не на каждый запрос).
- Потоковая выдача данных: асинхронный генератор (`async def` с `yield`), потребление через `async for`. Закрывай генератор, если выходишь из цикла досрочно (`contextlib.aclosing`).
- Своя блокировка состояния: `asyncio.Lock`. Не используй `threading.Lock` внутри корутин.
- Общение между задачами: `asyncio.Queue` с ограничением размера (`maxsize`), чтобы был обратный отсчёт нагрузки (backpressure).

## Ошибки и повторы

- Ошибку каждой задачи обрабатывай или пробрасывай явно; необработанное исключение в фоновой задаче только пишется в лог и теряется.
- Повторы: экспоненциальная пауза с разбросом (jitter); правила повторов и таймаутов вне async см. `SKILL.md`.
- Для недоступного сервиса предусмотри быстрый отказ (circuit breaker или ограничение очереди), а не бесконечное ожидание.

## Типичные ошибки

- Забытый `await` (результат — объект корутины, предупреждение `never awaited`).
- Блокирующий вызов в корутине.
- `asyncio.run` внутри уже запущенного цикла (в Jupyter и обработчиках фреймворка).
- Задачи без хранения ссылки и без обработки исключений.
- `gather` без ограничения числа задач.
- Проглоченный `CancelledError`.
- Использование `asyncio.get_event_loop()` вместо `asyncio.get_running_loop()` внутри корутин.

## Чек-лист

- В каждой корутине нет блокирующих вызовов.
- Параллелизм ограничен, у ожиданий есть таймаут.
- Фоновые задачи под управлением (`TaskGroup` или сохранённые ссылки), ошибки обработаны.
- `CancelledError` не проглочен, ресурсы закрываются через `async with` или `finally`.
